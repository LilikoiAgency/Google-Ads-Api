# SEO Audit v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single-shot SEO audit with a resumable analyst pipeline: correct, richer data, then four focused analysis passes, then a synthesized, evidence-backed Action Plan plus a client summary.

**Architecture:** Pure modules under `src/lib/seoAuditV2/` (data mapping, task ordering, job state machine, pass definitions), thin I/O wrappers (Search Console, PageSpeed, model calls, Mongo job store), three API routes under `/api/seo-audit/v2/jobs`, and a v2 results view in the existing SEO Audit page. Each job step is its own request, under about 4 minutes.

**Tech Stack:** Next.js 14 app router, `googleapis` (searchconsole v1, webmasters v3), the AI SDK already used by the v1 audit route (streaming, `output_config.format` JSON schema), MongoDB via `src/lib/mongoose.js`, vitest.

**Spec:** `docs/superpowers/specs/2026-11-18-seo-audit-v2-design.md`. Read it; the task shape, step list, Quick vs Full table, and failure, reuse and history rules all live there.

## Global Constraints

- Work on `main`; commit per task; never push, never open PRs.
- **No mention of the AI vendor or "AI-generated" anywhere**: commit messages (no `Co-Authored-By` trailer), docs, code comments, UI copy, client output. Model IDs appear only as a constant in `src/lib/seoAuditV2/llm.js`.
- Model: `AUDIT_MODEL` is the most capable current model; the exact ID is given in the task dispatch. Thinking is adaptive (omit `thinking`). Effort goes in `output_config.effort`. Always stream and use `.finalMessage()`, with `max_tokens: 32000`. Never send `temperature`, `budget_tokens`, or forced `tool_choice`.
- Structured outputs: every model call passes `output_config: { effort, format: { type: "json_schema", schema } }`. Check `stop_reason` before reading content: `refusal` and `max_tokens` are failures for retry.
- Every v2 route: `getAllowedSession()` (401 otherwise), `export const maxDuration = 300`, `export const dynamic = "force-dynamic"`. Responses and logs carry only `err.message`/`code`, never whole error objects.
- Data gaps use the existing status vocabulary: `ok | not_connected | no_site | no_property | no_data | error`, plus `permission` and `timeout`.
- Quick vs Full exactly per the spec table: pages 5/50, URL Inspection 5/20, PageSpeed 2/5, effort `medium`/`high`.
- Daily limit `DAILY_LIMIT = 5` per non-admin user and the monthly budget cap (`getMonthlyClaudeCost`/`getClaudeBudgetCap`) are enforced exactly as in `src/app/api/seo-audit/analyze/route.js`. Log usage per model call through `logApiUsage` with `feature: 'seo_audit_v2'`.

## Review Focus

1. **A site with no Search Console or GA4 access** (any prospect domain). The pipeline must still finish with crawl-only passes and clear `data_gaps`, and no task may cite Search Console numbers. Test: Task 3 `gather with all sources missing`; Task 5 `pass input omits unavailable sources`.
2. **A pass that times out or is refused twice.** The job finishes `done` with that area in `data_gaps`; it never shows `done` with silent holes. Test: Task 6 `failed pass becomes a gap after retries`.
3. **Two tabs calling `advance` at once.** A step must not run twice. Test: Task 6 `running step under 6 minutes is not re-run`; Task 7 `atomic claim prevents double run`.
4. **Sitemap index with nested indexes, gzip, or a robots.txt-only sitemap.** Test: Task 1.
5. **Very long pages, or pages with hundreds of images.** The input must stay bounded (8,000-character text, image summary). Test: Task 1 `page record caps text and summarizes images`.

### Task 4: Task model — schema, priority, dedupe

**Files:** Create `src/lib/seoAuditV2/tasks.js`. Test: `src/__tests__/lib/seoAuditV2/tasks.test.js`.

**Interfaces — Produces:**
- `TASK_JSON_SCHEMA`: the JSON schema for one task, exactly the spec's task shape. `category` is an enum of `technical, content, local, aeo, conversion`; `impact` and `effort` are `{ "type": "integer", "enum": [1,2,3,4,5] }`. Structured outputs don't support numeric min/max, so use only `type`, `enum`, `properties`, `required`, `items`, `additionalProperties` and `minItems` of 0 or 1; `confidence` is an enum of `high, medium, low`; `evidence` is a string array with `minItems: 1`; `additionalProperties: false`.
- `priorityScore(task) -> number` = `impact * {high:1, medium:0.7, low:0.4}[confidence] / effort`.
- `mergeTasks(taskLists) -> task[]`. Merges tasks with the same `page` and a near-identical title (lowercased, punctuation stripped, first 6 words equal): keep the higher score and union the evidence. Then sort by `priorityScore` descending and re-number ids `T1..Tn`.
- `isGenericTask(task) -> bool`. True when `page === 'site-wide'` and the change has no quoted text or path, or when the title matches `/^(improve|optimi[sz]e|enhance|build) (content|seo|backlinks|quality)/i`. Used to drop tasks.
- `tasksToCsv(tasks) -> string`. Columns: Priority, Task, Page, Category, Impact, Effort, Confidence, Change, Evidence (joined with ` | `). Quotes are escaped per RFC 4180.
- [ ] **Step 1: Failing tests:** priority ordering; merge of duplicates across passes; `isGenericTask` positive and negative examples; CSV escaping of quotes and newlines.
- [ ] **Step 2–4:** fail → implement → pass.

Each pass gets only its slice, per the spec table. `content` returns **an array of chunks**, at most 8 pages per chunk, each page with `content_text`, title, meta, headings and its joined queries. `pass input omits unavailable sources`: a null source is omitted, never sent as empty arrays.

### Task 6: Job state machine (pure)

**Files:** Create `src/lib/seoAuditV2/jobs.js`. Test: `src/__tests__/lib/seoAuditV2/jobs.test.js`.

**Interfaces — Produces:**
- `STEP_KEYS = ['crawl', 'gather', 'pass:technical', 'pass:content', 'pass:local', 'pass:conversion', 'synthesize']`
- `newJob({ email, domain, auditType, now }) -> job`. Has `version: 2`, status `queued`, and every step `pending` with `attempts: 0`.
- `runnableSteps(job, now) -> string[]`. Dependencies: `gather` after `crawl`; all passes after `gather`, returned together; `synthesize` after every pass is `done` or `failed_final`. A step that is `running` with `startedAt` less than 6 min ago is not runnable. One that's 6+ min old counts as stale and becomes runnable again.
- `applyStepResult(job, key, { ok, error }, now) -> job`. On failure, attempts go up by 1; at 3 attempts (1 + 2 retries) the step becomes `failed_final`. A pass that is `failed_final` adds a gap (`"<Area> analysis didn't complete — rerun to include it"`). If `crawl`, `gather` or `synthesize` is `failed_final`, the job is `failed`. When synthesis is done, the job is `done`.
- `effortForAttempt(baseEffort, attempts) -> 'high'|'medium'|'low'`. Steps down one level per retry.
- `shouldRefund(job) -> bool` = `job.status === 'failed' && !job.result`.
- [ ] **Step 1: Failing tests:**
  - order of runnable steps;
  - all 4 passes runnable together;
  - `running step under 6 minutes is not re-run`;
  - stale running step becomes runnable;
  - `failed pass becomes a gap after retries` (job reaches `done` once synthesis completes; the gap is listed);
  - crawl failing 3 times makes the job `failed` with `shouldRefund` true;
  - effort steps down.
- [ ] **Step 2–4:** fail → implement → pass.
- [ ] **Step 5: Commit.** `feat(seo-v2): resumable job state machine`

### Task 7: Job store and API routes

**Files:**
- Create `src/lib/seoAuditV2/jobStore.js`, `src/lib/seoAuditV2/runStep.js`.
- Create the routes `src/app/api/seo-audit/v2/jobs/route.js` (POST), `src/app/api/seo-audit/v2/jobs/[id]/route.js` (GET), and `src/app/api/seo-audit/v2/jobs/[id]/advance/route.js` (POST).
- Modify `src/app/api/seo-audit/history/route.js` to include jobs.
- Test: `src/__tests__/api/seo-audit-v2.test.js`.

**Interfaces:**
- `jobStore.js`, collection `SeoAuditJobs` in db `tokensApi`:
  - `createJob(job)`, `getJob(id)`
  - `claimStep(id, key, now) -> bool`: an atomic `updateOne` that only matches when the step is `pending` or stale `running`. It's the guard for `atomic claim prevents double run`.
  - `saveStep(id, key, patch)`, `findReusable({ domain, auditType, todayStart }) -> job|null` (an in-progress job, or a `done` job from today), and `saveFinished(job)`, which also inserts into `SeoAudits` with `version: 2`, `auditResult: job.result`, and the scores mapped to the v1 field names.
- `runStep(job, key) -> Promise<{ ok, patch, error }>`. Dispatches:
  - `crawl` → `seedPages` + `crawlSite`
  - `gather` → `gatherAll`
  - `pass:*` → `buildPassInput` + `runStructured` (content chunks run in parallel and their outputs are merged), then drops tasks via `isGenericTask`
  - `synthesize` → `runStructured` with all pass outputs, then `mergeTasks`
  - Large step outputs are stored on the job (`data`, `passes`, `result`).
- Routes:
  - **POST `/jobs`** `{ domain, auditType: 'full'|'quick', forceRerun? }`. Order: zod validation → session → reusable check (skipped when `forceRerun`) → admin/daily-limit → budget cap → increment usage → create. Returns `{ jobId, reused }`.
  - **POST `/jobs/[id]/advance`**: computes `runnableSteps` and claims each one. The passes run with `Promise.allSettled`. Applies the results, refunds usage when the job ends `failed` (`$inc: -1`), and returns the progress shape.
  - **GET `/jobs/[id]`** returns progress, plus `result` when done.
  - **Progress shape:** `{ jobId, status, steps: [{ key, label, status }], dataGaps: string[], result? }`. `dataGaps` holds finished sentences from `describeGaps` on the server. Labels: Crawling pages / Reading Search Console, Analytics & page speed / Technical & indexing / Content & keywords / Local & AI search / Conversion / Building action plan.
- History: add jobs that aren't done (`status: running|queued|failed`) to the list, with a `status` field. Existing items get `status: 'done'`.

  - the daily limit blocks a non-admin at 5;

  - a failed job refunds usage;
  - `atomic claim prevents double run` (the second claim returns false, so the step isn't executed);
  - GET returns `result` only when done.
